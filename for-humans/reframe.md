# Reframe: Finding the Problem Worth Solving

## What This Is

Reframe is for stepping outside the current frame of a problem when the frame itself is wrong or limiting. It does not analyze the problem — it questions whether the problem is being held correctly in the first place.

The difference between reframe and other skills: every other skill takes the problem as given and thinks harder about it. Reframe asks whether the problem as given is the right problem.

---

## When to Use It

Reframe is not the first skill to reach for. It's the skill you reach for when other skills are producing effort without traction.

Specific signals:
- You've speculated, reconsidered, or challenged the problem and solutions feel unsatisfying without a clear reason why
- The problem keeps returning in a different form after being solved
- Every solution generates a new problem of equal weight
- The question feels wrong but you can't say why
- There's broad agreement on the problem but persistent disagreement on solutions — often a sign that different people are solving different problems under the same label
- You feel stuck in a way that more analysis won't fix

If none of these are present, you don't need reframe. Use a different skill.

## How to Do It

### Step 1: State the current frame explicitly

Before you can step outside a frame, you have to see it clearly.

Write the problem as it's currently held:
- What's being solved?
- What's assumed to be fixed (constraints)?
- What's assumed to be variable (the solution space)?
- What does success look like within this frame?

Make the implicit explicit. Most frames are invisible until stated.

### Step 2: Identify the frame's load-bearing assumptions

Every frame rests on assumptions about what the problem is, what caused it, who owns it, and what a solution would look like.

For each assumption ask: is this actually true, or is it inherited?

Common sources of inherited assumptions:
- How the problem was first described
- Who first named it and what they cared about
- What solutions have been tried before (framing by elimination)
- What vocabulary is being used (language carries frames)

### Step 3: Question the problem statement itself

Ask these in order:

**Who defined this as a problem?** And for whom is it a problem? The same situation is often a problem for one party and a feature for another.

**What would have to be true for this not to be a problem?** This surfaces the assumption that makes it a problem. Sometimes that assumption is wrong or changeable.

**What is the problem a symptom of?** Solving the symptom often produces a new symptom. What's the underlying condition?

**What problem are we not allowed to name?** Some frames exist specifically to avoid a harder or more uncomfortable problem. What is this frame protecting against?

**If we couldn't solve this problem, what would we do instead?** The alternative path sometimes reveals that the original problem was optional.

### Step 4: Generate alternative frames

With the original frame's assumptions loosened, generate at least three genuinely different framings of the situation.

Not variations — genuinely different. A different frame changes who owns the problem, what success looks like, or what the solution space is.

For each alternative frame ask:
- What becomes possible in this frame that was impossible in the original?
- What becomes impossible that seemed necessary?
- Who benefits from this frame? Who's disadvantaged?

### Step 5: Choose a frame deliberately

You're not looking for the "true" frame. Frames are tools, not facts. You're looking for the frame that is most useful for the actual goal.

Ask: which frame produces the most tractable problem? Which frame opens the most valuable solution space? Which frame, if worked within, would produce something worth having?

Choose that frame. State it explicitly. Note what it gains and what it gives up.

## The Relationship Between Reframe and Question 1

*Skill-master*'s first question asks: "What am I actually being asked?"

That question catches surface misreads — answering the wrong literal question, missing the real need behind an explicit request.

Reframe goes deeper. It's for situations where even after correctly identifying what's being asked, the asking itself is wrong. Not the wrong question in this conversation — the wrong question entirely.

Question 1 fixes misreads. Reframe fixes misframes.

## Connections to Other Skills

**reframe → decompose:** Once you have the right frame, decompose breaks it into workable units.

**reframe → speculate:** A new frame opens a new solution space. Use speculate to explore it.

**reframe → review:** When you've generated multiple frames, use review to find what each frame sees that the others miss.

**discrepancies → reframe:** Discrepancies surfaces signals that something is wrong. Reframe addresses the possibility that what's wrong is the frame itself.

## Failure Modes

**Reframing as avoidance:** You reframe because the problem is hard, not because the frame is wrong. This produces a new frame that's easier to work in but less relevant to what actually matters.
Detection: The new frame feels more comfortable but doesn't produce better solutions.
Recovery: Return to the signal test. Is there actual evidence the frame is wrong, or is this discomfort with the problem?

**Infinite reframe:** You keep stepping back to higher levels of abstraction without ever landing somewhere you can work.
Recovery: A frame is only useful if it produces a tractable problem. If your reframe produces a problem no one can do anything about, it's not useful. Step back down.

**Reframe without commitment:** You generate alternative frames, find them interesting, and then return to the original because it's familiar.
Recovery: Reframe requires choosing. State the new frame explicitly. Commit to working in it. You can always return to the original — but you must actually try the new frame first.

**Premature reframe:** You reframe before genuinely working within the original frame. Sometimes the original frame is correct and the problem is just hard.
Detection: Have you actually tried speculate, reconsider, or challenge within the current frame?
Recovery: Exhaust the current frame first. Reframe is for stuck-ness that persists despite real effort.

---

## Success Criteria

This worked when:
1. You identified at least one load-bearing assumption in the original frame
2. You generated at least three genuinely different framings
3. You chose a frame deliberately and can explain what it gains and gives up
4. The new frame produces a different and more tractable problem
5. You feel the difference between working in the new frame and the old one

This failed when:
1. The alternative frames are variations on the original rather than genuinely different
2. You chose a frame because it was easier, not because it was more useful
3. You generated frames but didn't commit to one
4. The stuck-ness persists in the new frame — which may mean the problem is correctly framed and just hard
